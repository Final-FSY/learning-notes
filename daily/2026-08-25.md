## 学到的知识

- **Web Analytics 注入脚本的幂等写法**：批量改多个 HTML 时脚本要「已有则跳过」，重复跑不产生重复代码；注入位置优先 `</body>` 前（脚本不阻塞首屏渲染）。
- **.gitignore 会坑线上部署**：从 GitHub 拷来的项目自带的 .gitignore 可能忽略构建产物（如打包好的 JS），本地开发没问题，push 后线上就 404。**本站直接托管编译产物**时，要主动检查 .gitignore 并放行关键运行文件。
- **WebAudio 全合成音效**：号角/烟花/扫描音都能用 WebAudio API 合成，不依赖任何外部音频文件——国内网络环境下最稳的做法，还能省流量。
- **自包含 HTML 的妙用**：照片转 base64 内嵌 + 所有样式脚本内联，一个文件走天下（双击即开、可发微信、可归档），代价是文件变大（216KB）。
- **is-a.dev 被拒原因复盘**：维护者会自动检查申请时填的 Website Preview 是否可访问，**必须等网站真正部署上线后再提交 PR**，否则直接被机器人拒。
- **用户心理**：整蛊页面要有「参与感」——警告屏吊胃口、进度条给反馈、彩蛋给惊喜，60 秒倒计时制造紧迫感。这套交互设计放正经产品里也通用。

## 踩坑记录

1. **candybox 白屏根因是 .gitignore**：本地正常 ≠ 线上正常，push 后一定要 curl 线上验证关键 JS 返回 200。教训：以后从 GitHub 拷游戏目录进网站，先查 .gitignore 有没有忽略关键运行文件。
2. **照片 push 到根目录导致 404**：整蛊站照片初始放错路径，`git mv` 到 photos/ 解决——文件路径和 HTML 里引用的路径必须一致，改完要重新验证。
3. **CSS 动画导致自动化测试点不了按钮**：按钮浮动动画会让 playwright 点击坐标落空，需要 force 点击。
4. **CF Web Analytics 没有 IP 明细**：只有访问量/来源/设备等聚合数据，想要详细 IP 日志得上 Umami 自托管。
5. **is-a.dev 申请别急**：第一次 PR 就是栽在「网站还没上线就提交」，等部署完成、curl 验证 200 后再提。
6. **隐私边界提醒**：整蛊页放了同学照片 + 真名，公网可见，已提醒皮皮整蛊完随时撤——网站内容上线前都要过一遍「这玩意儿挂公网合适吗」。
