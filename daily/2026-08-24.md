## 学到的知识

- **认证与安全基本功**：密码加盐哈希存储（绝不存明文）、登录限速防爆破、token 有效期、路径穿越防护（拒绝 `..` 和隐藏文件）、文件名清洗、上传大小限制。这是任何带后台的网站都该有的底线。
- **raw body 上传 vs multipart**：上传接口可以不用表单格式，直接发原始字节 + 文件名放自定义请求头（X-Filename），后端更简单，前端 `fetch` 直接传 File 对象即可。
- **静态托管 vs 动态功能**：Cloudflare Pages / GitHub Pages 都是纯静态托管——没有服务器执行 Python，所以上传、后台、访问统计这类动态功能只能在自托管服务器上用。选托管方案前先想清楚网站要不要动态能力。
- **域名注册的国情课**：未成年人 + 无支付宝 + 家长不支持 = 国内注册商基本全卡（实名制），国外注册商（Porkbun/GoDaddy）支付渠道又挑人。**is-a.dev 这类免费子域名**（GitHub PR 申请、完全免费、无需实名）是学生党的完美绕行方案。
- **GitHub Pages 部署**：仓库名必须是 `<用户名>.github.io` 才能直接发布；在仓库 Settings → Pages 里选分支和路径即可，本质是把静态文件当网站托管。
- **SSH over 443**：网络环境封 22 端口或 HTTPS 大流量被掐时，SSH 可以走 443 端口（ssh.github.com），日常 git push 大仓库的救命稻草。
- **GitHub 用户名规范**：用户名只能小写字母、数字、连字符，所以 Final-FSY 实际是 final-fsy，仓库名必须完全匹配。

## 踩坑记录

1. **curl 测中文路径必须百分号编码**：http.server 的请求行按 latin-1 解码，原始中文会乱码；浏览器 encodeURIComponent 没这问题，但 curl 直接拼中文会 404。
2. **`startswith(base+sep)` 会漏掉目录自身**：/study/ 这个路径本身也需要重定向到 index，只判断子路径会漏掉它。
3. **sed 批量改导航时把自己匹配进去**：给 16 页统一加「学习」链接，结果 study.html 自己也被匹配，出现重复链接，要手动清。
4. **`cd xxx && nohup ... & sleep` 的坑**：`&&` 和 `&` 组合会让 cd 跑进后台子 shell，主 shell 没切目录，后面 `for f in *.html` 的 glob 直接失败。验证脚本要分开写（先 cd 再启动）。
5. **is-a.dev 格式变过**：2026 年字段从 `record` 改成了 `records`（复数），owner 要带 email；PR 必须用完整模板（勾选 TOS/DOMAIN_STRUCTURE/WEBSITE_REACHABLE/SOFTWARE_RELATED/NON_COMMERCIAL/CONTACT_INFO/WEBSITE_LINK + Website Preview 填现有可达网站链接）。
6. **`gh pr edit` 静默失败**：会因 GraphQL projectCards 报错，改用 `gh api -X PATCH pulls/48805 --input body.json` 才成功。
7. **GoDaddy 被墙实测**：DNS 污染到 Facebook IP（69.171.229.11），TCP 全超时——能付钱也白搭。
8. **仓库改名失败**：第一次用 Final-FSY.github.io（大写+原用户名），违反 GitHub 用户名规范，正确名是 final-fsy.github.io。
9. **HTTPS push 大文件被掐**：23MB 的 push 走 HTTPS 直接 TLS 中断，换 SSH over 443 秒通；gh-proxy 代理平时挂着，push 时要临时 unset。
