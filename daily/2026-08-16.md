# 2026-08-16 · 网络调整：DNS 回退 + Orange Pi 改无线

昨天 AdGuard Home 全屋生效后，发现它把不少正常网站也误拦了（比如一些冷门小站）。今天做两件事：**把 DNS 过滤从"全屋"退回"仅自用"**，以及**把 Orange Pi 从有线改成无线**（嫌桌上走线难看）。

### 📌 今天干了什么

1. **关闭全屋 DNS 过滤**
   - 用脚本调路由器 API 清空 DHCP 下发的 DNS 字段 → 全屋设备回落到默认 DNS
   - AdGuard Home 容器保留，自己设备**手动指定 DNS** 继续用
   - 验证：API 返回成功、配置已清空 ✅

2. **Orange Pi 有线改无线**
   - 装 NetworkManager（精简版系统没带），并禁用 systemd-networkd（防两个网络管家抢接口）
   - `nmcli dev wifi connect` 连上家里 WiFi
   - 踩了个大坑：**有线换无线 MAC 变了**，路由器上绑定的静态 IP 不认了
   - 路由器绑定 API 又全 404 → 干脆用 NetworkManager 直接配静态 IP（.151）
   - 停掉有线网卡，无线正式上岗；验证 IP、DNS 服务全部正常 ✅

### 🧠 学到的知识

- **DHCP 下发 DNS 的原理**：路由器 DHCP 服务会告诉全屋设备"用哪个 DNS"，改 DHCP 配置 = 全屋生效；租期 720 分钟，不重连的设备最迟 12 小时生效
- **有线网卡和无线网卡是两张不同的"身份证"（MAC）**：换网络方式 = 换 MAC = 之前的绑定全部失效
- **NetworkManager 三件套**：`nmcli` 命令行、`nmtui` 图形菜单（换 WiFi 用这个，一目了然）、静态 IP 直接写在连接配置里
- **带宽的"够用"判断**：2.4GHz 单频 WiFi 看着弱，但 Orange Pi 只跑 DNS 查询和轻量同步，占空比不到 1%，全家 5G 设备完全不受影响
- **改网络配置时 SSH 必断是正常现象**：IP 一变，旧连接立刻失效，用新 IP 重连即可；首次连新 IP 要加 `-o StrictHostKeyChecking=accept-new`

### 🕳️ 踩坑记录

| 坑 | 解法 |
|----|------|
| 换无线后 IP 丢了（MAC 变了） | NetworkManager 静态 IP 方案，不依赖路由器绑定 |
| 路由器静态绑定 API 全 404 | 放弃路由器方案，客户端自己配静态 IP |
| 改 IP 瞬间 SSH 断 | 正常，用新 IP 重连 |
| systemd-networkd 和 NetworkManager 抢接口 | 禁用前者，只留一个管家 |

### 💡 今日金句

> 换网络方式 = 换身份证（MAC）。所有"按设备绑定"的配置都会失效——遇到问题先查 MAC。

- 全屋 DNS 恢复正常，自己设备保留广告拦截 ✅
- Orange Pi 全无线运行，IP 固定 .151 不变，AdGuard 地址不变 ✅
