## 🧠 学到的知识

### 1. `nohup &` 为什么保不住后台进程？——`setsid` 才是正解

这是今天最值得记的一条，因为同一个坑踩了第二次。

- `nohup` 只做一件事：**忽略 SIGHUP 信号**（终端断开时内核发给前台进程组的「挂断」信号）
- 但 exec 会话结束时，清理动作不只是发 SIGHUP，还可能**直接对整个进程组下手**（SIGKILL/SIGTERM）
- 我的 python 进程和那个临时 bash 在**同一个进程组**里，父 bash 一死，进程组被端掉，nohup 挡不住

**正确姿势**：

```bash
setsid nohup python3 server.py >> server.log 2>&1 < /dev/null &
```

- `setsid` 让进程**新开一个会话**（session），彻底脱离原来的进程组和终端
- 判断成功：起来后 `ps -o pid,sid,cmd -p <PID>`，**sid == pid** 就说明它自成一个会话了
- 再稳一点：`disown` 从 shell 的作业表里摘掉；终极方案是交给 systemd 托管（见下一条）

### 2. 为什么「能跑的脚本」也应该写成 systemd user service

- 手动 `setsid nohup` 起的东西，**机器重启就没了**，挂了也没人拉
- user service 放在 `~/.config/systemd/user/xxx.service`，好处：
  - `Restart=always` 挂了自动重启
  - `systemctl --user enable --now` 开机自启（还要 `loginctl enable-linger fsy`，否则用户没登录时不会启动）
  - 日志统一进 journald，`journalctl --user -u xxx -f` 就能看
- 代价：改系统状态这类事得先跟人确认，不能自己偷偷装

### 3. 网关升级踩的四个坑，其实都是同一个主题：**权限 + 兼容性**

1. **为什么 `openclaw update` 自己升不动**
   - 全局包在 `/usr/lib/node_modules`（root 所有），网关进程以普通用户 `fsy` 跑，没写权限
   - 所以要 `sudo npm install -g`
   - 反过来说：**用 sudo 装的东西，跑它的进程不一定有权限改它**，这是个常见的错配

2. **npm 的 allow-scripts 把 postinstall 拦了**
   - 新版 npm 默认不执行依赖的安装脚本（防供应链攻击），这是好事
   - 但有些包的 postinstall 是**必需的**（比如安装 bundled 插件），得手动补：
     `sudo node scripts/postinstall-bundled-plugins.mjs`

3. **新版拒绝旧配置键**
   - 配置结构会随版本演进：`agents.defaults.memorySearch` → `memory.search`，`gateway.nodes.denyCommands` → `gateway.nodes.commands.deny`
   - 还有几个键直接删掉了（`meta.lastTouchedAt`、`gateway.tailscale.resetOnExit` 等）
   - 教训：**升级前先备份配置**，出问题能立刻回滚；今天备份了 `~/openclaw.json.bak-20261121` 等三份

4. **doctor --fix 不肯在旧网关进程跑着的时候干活**
   - 它检测到「进程版本 ≠ 安装版本」就判定 stale，拒绝迁移数据库 schema
   - 解法不是硬来，而是**按正确顺序**：停 → 迁移 → 启 → 健康检查
   - 用 `systemd-run --on-active=...` 排个延时任务来做，因为我自己就在网关里面，不能自己把自己停了还指望命令能跑完

### 4. systemd-run 排重启任务的两个细节

- 第一次用 `systemd-run --on-active=30s` 排的任务**根本没执行**，连日志文件都没建
- 换成 `--setenv=HOME=/home/fsy` + 命令里全部用**绝对路径** + 换个新 unit 名，就成了
- 原因大概是：非交互环境里没有 HOME，脚本里用 `~` 展开会失败/写错地方；同名 unit 冲突也会静默失败

### 5. 磁盘清理的正确顺序：先量，再分类，最后才删

- 先 `df -h` / `du -sh *` 找大头，别凭感觉
- 分三类处理：
  - **可再生的缓存**：直接清（npm/pip/apt 缓存、`~/.cache`）
  - **明确没用的**：确认后清（不用的 Ollama 模型、旧备份、旧镜像）
  - **用户数据**：**只能报告，不能自己删**（这点很重要，删错了没法救）
- 今天清出 4.4G 缓存 + 11G 没用到的模型 + 其他杂项，一共腾出 22G

### 6. crontab 里跑 `systemctl --user` 为什么找不到服务

- cron 的环境极简，**没有 `XDG_RUNTIME_DIR` 和 `DBUS_SESSION_BUS_ADDRESS`**，systemctl 不知道去哪找用户总线
- 必须在脚本里显式 export：

```bash
export XDG_RUNTIME_DIR=/run/user/1000
export DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/1000/bus
```

- 另外两个「监控阈值」的经验：
  - **负载**别按 CPU 核心数定死，树莓派编译/推理时轻松到 7+，按核心数会天天误报
  - **内存**别用「已用百分比」，Ollama 加载一个 2.2G 的向量模型就会假警报，看 `MemAvailable` 才准

### 7. 自动化任务的投递目标：`owner` 不一定有路可走

- 把 automation 的 delivery target 设成 `owner`，结果 no-route 失败——因为没配 owner 的私聊通道
- 改成 `sessionTarget=current`（在当前会话里投递）才通，实测 `delivered=true`
- 教训：**「发给谁」和「从哪发」是两件事**，路径不存在时再正确的目标也投不出去

### 8. MCP 是什么，以及 REA 是怎么接进来的

**MCP（Model Context Protocol）**：一个让 AI 助手接外部工具的标准协议。可以理解成「AI 的 USB 接口」——工具方实现协议，AI 这边就能发现并调用它的能力。

接入 OpenClaw 的配置长这样：

```json
{
  "mcp": {
    "servers": {
      "rea": {
        "enabled": true,
        "command": "/usr/bin/rea",
        "args": ["mcp"],
        "transport": "stdio"
      }
    }
  }
}
```

- `transport: stdio` 意思是：OpenClaw 启动这个子进程，通过**标准输入输出**跟它说话（而不是走网络端口）
- 改完配置**必须重启网关**才加载，重启后工具数 49 → 314
- 验证方法：先直接给 `rea mcp` 发一条 MCP `initialize` 请求做握手，拿到 serverInfo 就说明服务本身没问题；再看网关这边能不能调通

**REA 的定位**：给 AI agent 用的逆向工程工具链（原生二进制 / Electron / JS / .NET / 网页 / Android / 固件 / 运行时录制）。我这台机器上可用的 provider 只有 `rea-artifact-graph`、`rea-dotnet-static`、`sqlite`。

⚠️ **关键限制**：本机没有 Ghidra/IDA，所以**原生二进制的深度反编译做不了**，只能做静态结构分析这一层。想做完整反编译得去 Windows 电脑（192.168.31.50）上装，或者装 Ghidra（需要 Java 21）。

### 9. 逆向入门：一个 strcmp 校验程序是怎么被拆穿的

今天的教程核心流程，值得背下来：

1. `file demo` —— 先看是什么架构、有没有 strip
2. `readelf -h/-S` —— 看节区表和入口点
3. `strings -t x demo` —— 把可读字符串连**偏移地址**一起打出来，找提示语（比如 "wrong password"）
4. `readelf -S` 确认 **文件偏移 == 虚拟地址**（PIE 的小程序里常见），这样 strings 给的偏移能直接当地址用
5. `objdump -d` 找谁引用了那个字符串地址（xref），顺着找到校验函数
6. 逐条读汇编，看懂 `strcmp` 的返回值和分支条件
7. `gdb` 在 `strcmp` 下断点，看两个参数寄存器的实际内容，验证推断
8. 单字节 patch：把 `b.eq`（相等就跳）改成 `b.ne`（不等才跳），错误口令也能过

**ARM64 分支指令的一个要点**：`b.eq` 和 `b.ne` 只差最低位（0x…c0 vs 0x…c1），改一个字节就能反转逻辑——因为条件码编码在指令的 bit 0-3。

这些是**学习用的靶子程序**，自己写的、自己编译的。真实软件逆向涉及法律边界，教程里也专门写了一节。

## 🕳️ 踩坑记录

1. **改正在运行的会话文件 → 把自己会话搞崩了** 🔴🔴
   - 现象：一次提问突然报 `session file changed while embedded prompt lock was released`，随后会话被重置，聊天界面变成空白
   - 根因：上一个 run 为了清掉会话记录里的密钥，直接改写了网关**正在使用**的 `.jsonl` 会话文件。网关发现文件被外部改动 → 判定不一致 → 中止并重置
   - 教训（血泪）：**永远不要动正在使用的会话文件**。要擦敏感串只能：① 操作非活动会话；② 等会话轮换后再清；③ 改存储层配置
   - 顺带：旧密钥已从 sqlite、`.bashrc`、设备配置里换掉（新密钥已脱敏），旧密钥还得去后台手动删除

2. **infoscreen-server 从 8/27 挂到 11/21 都没人发现**
   - 因为没有任何监控。日志停在三个月前，data.json 里的天气还是 8/29 的
   - 直接催生了今晚的巡检脚本——**「服务在跑」这件事必须有东西替你盯着**

3. **Ollama 加载模型导致内存告警误报**
   - 一开始用「已用内存百分比」做阈值，Ollama 一加载 2.2G 的向量模型就报警
   - 改用 `MemAvailable < 150MB` 才反映真实压力

4. **`apt install openjdk-21` 报 404**
   - 不是包没了，是**本机 apt 索引过期**，指向的版本已经下架
   - 正确顺序：`apt-get update` 再装。这个错很容易误判成「软件源坏了」

5. **升级后微信通道挂了**
   - 插件 ABI 不兼容（plugin-sdk 没导出它要的符号），升 OpenClaw 大版本时第三方插件经常这样
   - 要在网关离线时跑 `openclaw plugins update openclaw-weixin`

6. **heartbeat 迁移成自动化后每 30 分钟空转**
   - 新的「Proactive check」payload 里 `skipIfScratchEmpty=true`，但 scratch 是空的 → 每轮都 skipped
   - 这个会话不是 owner，改不了它的 prompt，得去 Control UI 的 Automations 页面填 checklist 或关掉那个开关
   - 所以今晚干脆自己重建了一套：脚本巡检 + 2 小时一次模型兜底，省 token 也更靠谱

7. **Node 版本差点不够**
   - REA 的 `engines` 要求 node `^24.22.1`，而机器上还是 24.19.0
   - 幸好今天升级 OpenClaw 时顺手把 node 提到了 24.22.3，不然装不上
   - 教训：**装新工具前先看 `engines`**，别等报错才回头查
