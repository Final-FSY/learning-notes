## 学到的知识

- **HDMI-CEC 基础**：CEC 是 HDMI 上的双向低速控制总线（400bps），设备靠逻辑地址 + 物理地址互相发现。物理地址 0x1000 = 插在电视 HDMI 口 1 后面。电视遥控器即使 CEC 通了也只能转发部分键（方向/OK/返回/菜单），电源/输入/主页键电视留给自己。
- **mDNS 应答机制**：iOS 设备发现 AirPlay 靠「查询-应答」，不是靠被动听广播。App 只发广播不回应查询 = 苹果永远搜不到。这就是为什么 DLNA（bilibili/爱奇艺）能搜到、AirPlay 搜不到。
- **avahi + socat 可以假扮 mDNS 应答器**：avahi-daemon 发布 `_airplay._tcp` 服务（TXT 原样照搬盒子广播），socat 把树莓派端口 TCP 转发到盒子的 AirPlay 端口（54180），iOS 连树莓派就等于连盒子。
- **Android 12 后台服务限制**：App 进 idle 后，`am start` 冷启动不算用户操作 → 后台服务直接崩（BackgroundServiceStartNotAllowedException）。用 `monkey -p 包名 -c android.intent.category.LAUNCHER 1` 模拟用户点击启动，前台权限完整，全流程跑通。
- **`appops` 可以放行后台启动**：`cmd appops set <包名> RUN_ANY_IN_BACKGROUND allow` 防崩溃。
- **PhoenixCard 升级模式 vs 量产模式**：升级模式只重写系统分区、保留 userdata；量产模式全盘重刷。以后刷机优先用升级模式。
- **全志私有 MFPK 容器**：super 分区不是 raw ext4，是全志私有容器格式（表在偏移 12544，每项 52B），外部无法直接修复，只能重刷。
- **三星电视自动唤醒的真相**：不只有 One Touch Play 一条路径——盒子在 CEC 总线重新现身（地址声明/物理地址变更）也会触发电视切换+唤醒。盒子端设置会被 vendor 秒级强制恢复（`settings put global hdmi_control_enabled 0` 写入后立即被改回 1），别浪费时间对抗。
- **FIFO 无读方时写入会无限阻塞**：`echo > fifo` 在没有读方时永久卡住，会让上层管道全部排队积压，表现为「按键失效」「长按停不下来」。

## 踩坑记录

- **改系统分区前先看空间！** /vendor 分区只有 104M 且 100% 满（剩 336K），任何写入都失败，还会留下 0 字节/损坏文件 → 重启直接卡 Logo 变砖。教训：`df` 看空间是改系统分区的前置步骤。
- **XML 里引号是 `&quot;`**：sed 改 shared_prefs 时 & 要转义，直接匹配 `"` 会失败。
- **AirScreen 首次启动 `userAccept:false`**：用户协议没勾 → AirPlay 服务不启动；改成 true 后 status 仍为 close（「启动即注销」），要 `adb shell am broadcast -a reg.airplay -p <包名>` 手动拉起来。
- **蓝莓投屏的 mDNS 应答器是坏的**：只发广播、从不回应查询（T+0s 查询测试、单播查询全部无响应）→ 必须用 avahi 假扮应答器兜底。
- **`am start` 冷启动必崩**：时灵时不灵的根源是 Android 12 后台服务限制，必须用 monkey 模拟用户启动。
- **CEC 设置会被固件重置**：重启后 `hdmi_control_enabled` 被改回开（vendor 有监控强制恢复）；但 `hdmi_control_tv_wake_on_one_touch_play 0` 和 `hdmi_control_tv_send_standby_on_sleep 0` 这两个开关重启后能存活。
- **注入器进程死后服务器看门狗没拉起来**：60s 周期 + 只查 ps 不够，改成 30s 周期 + ps 检查 + FIFO 写 0 实测（僵尸检测）+ 自动重部署。
- **FIFO 写要加超时**：`timeout 1` 让注入器死了也不卡管道。
- **快进键码用错了**：87 是 MEDIA_NEXT（下一集），快进应该是 90（MEDIA_FAST_FORWARD）。
- **pkill -f 会匹配到自己的命令行**：又一次确认这个坑（上回 8-20 也踩过）。
