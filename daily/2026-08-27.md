## 学到的知识

### 1. OAuth 授权码是一次性的
小米登录报 `error:96013 invalid authorization code` 后，点重试会**复用同一个已经失效的授权码**，永远失败。正确姿势：失败后整个登录流程重新开。这是 OAuth 的通用特性——授权码（authorization code）用一次就作废，就像电影票，检票后就不能再用了。

### 2. mDNS 广播的"版本坑"
Home Assistant 新版（2026.2.3）的 zeroconf 只广播 `{uuid}._home-assistant._tcp`（服务器名是 `uuid.local`），**不再广播 `homeassistant.local`**。而小米 OAuth 回调地址写死 `http://homeassistant.local:8123`（配置里锁定不可改），小米又拒绝 IP 回调——所以必须自己想办法让 `homeassistant.local` 能解析。
**解法**：用 avahi 发布 A 记录（`avahi-publish -a -R homeassistant.local <IP>`），而不是只写 service 文件——service 文件不产生 A 记录，这是最容易搞错的一点。脚本开机自启（systemd + Restart=always），自动取当前网卡 IP。

### 3. 大模型会"编造"设备 ID，必须给它真实列表
排查发现：设备列表从来没成功注入过大模型的提示词（代码有两个 bug：① 条件字符串写错；② YAML 列表被当字符串拼接，TypeError 被 except 吞掉）。结果就是大模型不知道真实设备，只能**瞎编 entity_id**——这解释了为什么之前语音控制会莫名失败。
修复后：给 8 个常用设备改了好记的实体名（如 `cover.yangtai_liangyijia`、`light.keting_deng`），减少大模型编造的可能。

### 4. 硬件不支持的功能，可以用"软件计时 + 急刹"实现
晾衣架的 MIoT 规格只有 `motor-control`（0=暂停/1=上升/2=下降），没有 `target-position`，**无法直接设位置**。但实测上升全程 ≈28s，所以"升到一半" = 开马达跑 14 秒 → 暂停。软件里维护位置文件（`cover_position.json`），每次开关都同步更新。
关键细节：刹车用 `asyncio.shield` 保护——即使客户端断连，马达停止命令也必须执行完。

### 5. 音质阶梯：flac → 320 → 128
腾讯音乐接口对免费用户限制音质，VIP 歌曲的 flac/320 会返回 400（错误码 104003 = 需会员）。策略：逐级尝试，能拿多高拿多高，拿不到自动落回 128kbps。VIP 账号到位后自动吃满。

### 6. WebSocket 发送大音频会被拒
单帧音频超过 ~1MB，websockets 客户端会直接 1009 错误断连。48kHz 采样率下 5 秒音频就超 1MB——所以闹钟语音必须**分块发送**，而且放音乐时要**限速**（1 秒音频等 1 秒），否则浏览器缓冲积压，喊停之后还要播半天。

### 7. 采样率配置看服务器，不看客户端
小智服务器的输出采样率由服务器自己的配置文件决定（`audio_params.sample_rate`），不是看客户端 hello 里声明多少。所以升级音质要改服务器的 24000 → 48000，同时改 Web 桥和浏览器端保持一致（48kHz 下帧大小 2880 = 60ms，缓冲阈值 5760 = 120ms）。

## 踩坑记录

| 坑 | 现象 | 根因 | 解法 |
|---|---|---|---|
| 装错集成 | 登录报"无法登录 Xiaomi Home" | 装的是 HA 内置的 `xiaomi_miio`，不是官方 `ha_xiaomi_home` | 从 GitHub 克隆自定义集成到 `custom_components/xiaomi_home`（v0.4.7） |
| OAuth 重试死循环 | `error:96013` 反复失败 | 授权码一次性，失败后重试复用死码 | 失败后整个流程重开 |
| `homeassistant.local` 不解析 | 小米回调打不开 | 新版 HA 不再广播该域名 | avahi 发布 A 记录 + 开机自启脚本 |
| 服务文件不生效 | 写了 avahi service 文件还是解析不了 | service 文件不产生 A 记录 | 用 `avahi-publish -a` 显式发布 |
| 设备列表没注入 | 大模型编造 entity_id | 条件写错 + 列表拼接 TypeError 被吞 | `"\n".join(devices)` + 在增强提示词构建**之后**追加 |
| 代码文件损坏 | QQ 音乐免费歌也 400 | `routes/song.js` 第 106 行 `outCharset: 'utf-8¬ice=0'`，参数被编辑弄成乱码 | 修复为 `outCharset: 'utf-8', notice: 0,` |
| 随机歌总同一首 | 3/3 次同一首 | 本地库只有 3 首（3 连同一首只是 1/27 巧合）+ 大模型拿"随机"当歌名 | 加随机模式从排行榜选 + 函数描述引导 + 禁用本地 play_music |
| 闹钟语音断连 | 音频发不出去 | 单帧 >1MB，websockets 1009 拒连 | 分块发送 + 1 秒音频等 1 秒限速 |
| 蓝牙日志刷屏 | HA 日志被 hci0 错误刷满 | 树莓派蓝牙权限问题 | 待办，不影响米家，后续处理 |
| 实体改名无 API | REST 没有改名端点 | HA 的设计如此 | 走 WebSocket API `config/entity_registry/update` |
