## 🧠 学到的知识

### 1. 网站仓库结构 & GitHub Pages 的两种模式

- 仓库是 `Final-FSY/final-fsy.github.io`，本地目录在 `~/website`
- 这个仓库名本身就是特殊用法：`<用户名>.github.io` 这种命名，会让 **main 分支的根目录**直接成为网站根目录，叫 **legacy Pages**（老式发布方式）
- 另一种方式是 GitHub Actions 发布（可以先把源码构建再上传），适合用框架（如 Jekyll/Hugo/React）的站点
- 我这种纯静态 HTML 直接扔根目录最省事：**改完 push，等几十秒就生效**

### 2. 网页读音频：为什么要量「响度」

- 音频参数：`audio/aihecheng.mp3`，时长 4:04，48kHz 立体声，177kbps
- 关键指标是 **-13.8 LUFS**。LUFS 是"感知响度"单位，不是峰值音量：
  - 峰值（dBFS）只管"最大声的那一下会不会爆"，不管整体听感响不响
  - LUFS 综合人耳对不同频率的敏感度，衡量"整体听起来多大声"
  - 流媒体平台一般把 -14 LUFS 当基准，**我的 -13.8 刚好合适，不用再做归一化处理**
- 教训：拿到音频先量响度，别凭感觉拧音量——响度太低平台会自己压/提，动态就毁了

### 3. 怎么把大文件从手机传到树莓派（今天最有用的技能）

**背景问题**：webchat 发不了 mp3 附件。想传个 5MB 的歌进树莓派，常规路都不通。

**思路**：树莓派和手机在同一个 Wi-Fi 里，那就在树莓派上开个**临时网页服务器**，手机浏览器打开上传。

**做法**：
- 用 Python 的 `http.server` 写一个子类，自己处理 `do_POST`
- 关键点：**直接读原始请求体（raw body），不走 multipart 表单解析**
  - 解析 multipart 要处理 boundary 分隔符、各种 header，自己写容易出错
  - 手机端用 `fetch(url, {method:'POST', body: file})` 直接甩二进制上来，服务端 `rfile.read(content_length)` 一把收完，简单可靠
- 手机打开 `http://192.168.31.187:PORT/up-<一串随机字符>` 上传
  - 路径里带随机 token，是为了防止别人在局域网里瞎逛撞到你的上传口
  - 这只是临时方便，不是安全设计——用完就该关
- 脚本留在 `~/aihecheng-upload-server.py`，文件落到 `~/aihecheng-upload/`

**备选方案（也值得记）**：
- 把 mp3 改名成 `.zip` 再发聊天（很多聊天工具只拦特定扩展名，换个马甲就过了）
- 直接用 GitHub 网页把文件拖进仓库（最省事，还顺便完成了上传到网站）

### 4. 树莓派的网络身份

- 局域网：`192.168.31.187`（wlan0，无线网卡）
- Tailscale 虚拟内网：`100.113.153.64`（在外面也能连回家）
- 同一个服务，局域网走前面的地址，外网走后面的——**两个地址指向同一台机器**

## 🕳️ 踩坑记录

1. **`pkill -f upload-server.py` 把执行这条命令的 bash 自己也杀了** 🔴
   - 原因：`pkill -f` 是**匹配整条命令行**。我执行的那条命令里本身就含有 `upload-server.py` 这串字符，于是它匹配到了自己（父进程 bash），一刀下去连自己一起没了
   - 表现：终端直接断开/命令没回显，服务器还活着或者莫名消失，很迷惑
   - 正确写法：`pkill -f "upload-server[.]py"`
     - 用方括号把点包起来，正则里 `[.]` 只匹配真正的 `.`，而命令行里那串字面量 `upload-server[.]py` 匹配不上自己——**经典的"防自杀"技巧**
   - 或者老实一点：先 `ps aux | grep -F upload-server.py` 看清楚 PID，再 `kill <PID>`

2. **GitHub Pages 拉 5MB 的音频很慢（≥90 秒）**
   - 页面能开，但音频加载卡很久。用 `curl -I` 测 HEAD 请求是正常的，说明服务器没问题，是**大文件传输在国内网络下慢**
   - 这跟 8 月 28 日那个"GitHub 直连不稳定"是同一类问题：**小请求能通，不代表大流量能跑**
   - 解法方向：音频压缩（降码率）、换 CDN、或本地缓存

3. **老域名 `finalfsy.eu.org` 已经废了**
   - DNS 解析不出来，等于这个域名不再指向任何地方
   - eu.org 是免费域名，稳定性本来就一般。以后引用网站地址要只用 `final-fsy.github.io`
